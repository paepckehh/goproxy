# AGENTS.md

`paepcke.de/goproxy` — single-binary go proxy, public mirror at
github.com/paepckehh/goproxy, BSD-3-Clause (see LICENSE).
Local-first long-term module archive: the cache is storage, not a
disposable buffer. Fetched modules are stored as received, never expired,
served from disk, and can be copied or backed up in the standard `download/`
layout. Upstream bandwidth is spent only on a true cold miss, which
de-clouds builds and reduces dependence on upstream uptime, rate limits and
policy churn.
- modern single binary, cgo and runtime dependency free
- fast: modern caching go mod proxy; a fleet chains warm caches via
  NEIGHBOUR_CACHES (parallel peer lookup before the upstream)
- secure: validates upstream signatures
- cool: modern 3D animated business-like dashboard about packages, sources,
  cache hits/misses, the 25 most requested modules, top 10 clients by
  requests and by bandwidth, process memory (RSS, Go heap, goroutines)
  against the systemd cgroup limit, neighbour-cache hits and
  peer bandwidth, live neighbour-cache health (online state, version,
  latency), pre-cache sync details, upstream and downstream bandwidth used
  and saved, store size, plus long-term (24h to all-time) history charts
- persistent: long-term stats in the SQLite stats database via the pure-Go
  cgo-free driver `modernc.org/sqlite`; lifetime counters, per-module
  served-bandwidth totals, per-client request/bandwidth rankings,
  minute-resolution buckets and the event log all survive reboots; a nightly
  23:00 local window checks, compacts, verifies and archives the database
  into eight gzip generations

KEEP ALWAYS AGENTS.md and README.md up-to-date for correct documentation.

## Layout

                     memory sampling, lazy recorder batches

                     pages, 15-minute bundled flush, minute buckets, clients
                     table, nightly check/compaction/backup)

                     fetch, verify, cache; fetches detached from client contexts);

Storage model: zips stored as-received (already deflate-compressed) under
`<root>/download/<escaped module>/@v/`; signed checksum records as `<version>.sum`
sidecars; index fully in memory, rebuilt by parallel scan at startup. Long-term
stats persist in the stats database (SQLite, WAL) in the default state dir
`/var/lib/goproxy` when it exists (the systemd units get it via
`StateDirectory`), else `<root>/stats.db` for unprivileged local runs:
lifetime totals table, one
bucket per minute (requests/hits/misses/bytes + store-size snapshots, kept
forever), per-module access counters (requests/bytes served/last use),
per-client counters (requests/bytes/last
seen, keyed by X-Forwarded-For or socket address, bounded to 4096 entries
in memory, monotonic MAX upserts so a counter reset
from an evicted entry can never shrink the stored lifetime totals; the
nightly window prunes rows older than 90d and caps the persisted table at
the same 4096 busiest clients), and the event log
(pruned after 90d). All of those dashboard counters are buffered in memory
and written together in one very large lazy transaction at most every
15 minutes and once on shutdown: 64 KiB pages, `synchronous=OFF`, no
automatic checkpoints, no fsync/force on the counter path. A crash loses
at most the unflushed window. The
dashboard is driven
entirely by one Server-Sent Events stream (`/api/events?range=`): it seeds
the event ring, counters, cache table, most-requested list, client
rankings, pre-cache report
and the selected history series on connect, then pushes each new event, the
counters every 2s, the cache table, most-requested list and both client
rankings only when they
changed (no idle table reloads), the pre-cache report only when a pass
finished, the history series every 30s, and a `tick` every 25s. Sections run
top to bottom: KPIs (including process RSS/heap/goroutines against the
cgroup limit), 3D top-modules chart, 25 most requested modules,
top clients by requests and by bandwidth,
neighbour caches, pre-cache sync, long-term history, archived modules plus
events, and the traffic chart last. A non-blocking fan-out keeps a slow client
from stalling the collector. The page is push-only: it never fetches
dashboard data, never polls and runs no refresh timer, so an idle tab costs
one open stream. Browsers without EventSource get no dashboard updates. The
page appends event rows instead of rebuilding the list, and reconciles the
cache table in place (rows keep their DOM nodes, only cells change and the
row fade animation is gone), so pushed updates never flicker or reload it.
The same reconciliation keeps both client rankings and the most-requested
table in server order. Deep links (`#clients`, `#history`, ...) use one
animation-frame scroll after the pushed state settles, not a refresh timer.
The request hot path never
touches the DB: atomics + buffered channel, one bundled lazy transaction at
most every 15 minutes plus a final flush and WAL checkpoint on shutdown;
recorder errors surface as warning
pills in the dashboard header (`persistErrors`, dropped events) and never
degrade proxying. Legacy pre-SQLite
`stats.json` snapshots migrate into `stats.db` on first start (renamed to
`stats.json.imported`).

Nightly maintenance: at 23:00 local time a goroutine (cmd/goproxy
maintenance.go) runs `history.DB.Nightly` without restarting or pausing
serving: semantic check (`PRAGMA quick_check`, present totals row,
non-negative counters, no future-dated events/clients, lifetime requests
never behind bucket history), event/client pruning, `wal_checkpoint
(TRUNCATE)`, `VACUUM` + `ANALYZE` + `PRAGMA optimize`, a `VACUUM INTO`
snapshot built under a temporary name, verified read-only/immutable with
`quick_check`, renamed into place, gzip compression
(temp file + rename, original removed only after success), and an
eight-generation cycle in `<db>.backup.daily` (newest two always kept).
The window closes with a final WAL checkpoint so the live file rests
complete and the WAL empty; results are logged and pushed as a
`maintenance` event. A start after a missed window catches up once after
five minutes. The single SQLite connection serializes the window with the
recorder. The dashboard reads the client rankings and the history series
from memory (client table + 20s series cache); only the 15-minute lazy flush
and the nightly window touch the database. The process memory card samples
`/proc/self/status` RSS, Go heap and goroutines at most once per second and
shows the cgroup `MemoryMax` ceiling systemd installed.

Observability: the journal stays quiet by default. Per-request access
lines and routine failure detail (upstream dial errors, non-200 statuses,
checksum-database probes, unverified-private-module notices) are logged at
Debug level and appear only when the `DEBUG=1` environment variable is set
(add it to the unit's environment); deployments without it keep the journal
clean.
Security refusals (tampered content) and warnings stay at Error/Warn.
Startup state, warnings and the surfaced dashboard event feed remain
visible without DEBUG.

Neighbour caches: `NEIGHBOUR_CACHES` (comma/whitespace separated base URLs)
optionally points a proxy at other goproxy instances. On a cache miss every
neighbour is asked in parallel via the plain GOPROXY route; the first 200
wins and the losing requests are cancelled (their response headers are
bounded to `neighbourHeaderTimeout` = 5s, bodies stream without a limit).
Only a full peer miss reaches the upstream. Entries are validated at
startup (http/https + host) and duplicates are dropped; a proxy must not
list itself. Neighbour content is verified exactly like upstream content,
so peers are never trusted. Stats count a peer-served request as a local
miss plus a neighbour hit, with peer bytes tracked separately from upstream
bytes (`NeighbourHits`, `NeighbourMisses`, `BytesNeighbour`), persisted in
the totals and minute buckets and shown on the dashboard.

Fleet health: `internal/fleet` probes every configured neighbour through
`/healthz` at startup and every 10 minutes (5s per-probe timeout, parallel).
The dashboard's neighbour card shows each peer's online state, version,
latency and last check; the neighbour KPI adds the online count. The status
is part of the `store` SSE message, so it reconciles in place like the
module table and never triggers a reload. A dead peer never delays a
request: lookups keep racing it and simply lose.

Fleet sync: at startup (after the cache index scan, which supplies the
ranking) and then once per hour with ±10 minutes jitter, the proxy resolves
the latest version of the 100 most requested modules (only modules that
served at least one request; a cache with no traffic is never crawled) and
fetches their
`.info`, `.mod` and `.zip` through the normal fetch path
(`internal/proxy/warm.go`). Neighbour caches are therefore asked first and
one upstream copy serves the fleet. The pass logs one Info line, publishes
one `prewarm` event and keeps a `fleet.WarmReport` (`Warmer.Report`:
started, duration, next run, modules/fetched/failed/bytes/peer bytes and
one `WarmItem` per module with resolved version, bytes, peer bytes, peer
source and error)
that the dashboard's pre-cache card renders. It is not a client request, so
request/hit/miss counters stay untouched while its bandwidth still counts
as upstream or peer bytes (`Stats.Prewarm`).
The startup pass waits for the index scan so it does not run against an
empty ranking. Socket-activated on-demand deployments (`EXIT_ON_IDLE=1`)
skip the sync: the process exits after 30s idle, so a 100-module prewarm
would spend upstream bandwidth on a process that is about to disappear.

Checksum-database freshness: `sumdb.DB.RefreshLoop` refreshes the signed
tree head from the database at startup and every 15 minutes. `Refresh`
fetches `/latest`, verifies the note signature, refuses to roll the
persisted head back (tree size), writes it through the x/mod
compare-and-swap config path and replaces the in-memory client so the next
lookup starts from the
fresh timeline.

Version queries: a request for `/<module>/@v/<query>.info` where the query
is not a canonical version (`module.CanonicalVersion(ver) != ver`) is what
the go command sends for branches, short tags (`v1.2`) and commit hashes.
It is forwarded upstream with `no-store` and never cached: only the
upstream can resolve it and the answer moves. `validQuery` keeps such a
query a single path element. `.mod`/`.zip` requests still require a
canonical version (400 otherwise), and canonical versions (including
pseudo-versions and `+incompatible`) stay on the cached, verified path.

Security: misses are verified against sum.golang.org (note signature + tlog
tree + tiles) before caching; a hash mismatch refuses content (502); no
record serves unverified; a record without a hash line for a kind (custom
databases) serves that kind unverified, never refuses; checksum-db outages
(including missing tiles) fail closed when `-verify=true`. The
`/sumdb/<db>/...` endpoint forwards paths verbatim to the configured database
only (its name must match, others get 404), answers the go client's
`/sumdb/<db>/supported` probe locally, and records forwarded traffic in the
stats. Go clients can therefore run their full verification through the
proxy. Shared singleflight fetches are detached from
the requesting client's context and bounded by a 30-minute fetch timeout:
one disconnecting client cannot abort the
download the other waiters share, a completed download still warms the
cache, and a stalled upstream body cannot pin the fetch forever.

## Socket activation (env contract)

Serving mode is resolved at startup: passed systemd sockets win, then an
explicit `-addr` flag, then `BIND_ADDR`, then `:5100`. `SOCKET_ACTIVATION=1`
declares socket-activated deployment (warns and falls back to binding when
no descriptors were actually passed). `EXIT_ON_IDLE=1` (socket-activated
mode only) exits cleanly once no request has been in flight for 30s — with
the final stats flush and WAL checkpoint — since systemd re-arms the socket
and restarts on demand. Combine it with `Restart=on-failure`, never
`Restart=always` (idle exit is success and would loop otherwise). Both
bundled units bound crash loops with `startLimitBurst = 3` within
`startLimitIntervalSec = 30`: repeated failed starts leave the unit
`failed` instead of restarting forever.

## Stats database and cache location

The stats database location is fixed policy, not configuration: `/var/lib/goproxy/stats.db`
when the state dir exists (normally provided by systemd `StateDirectory`),
otherwise `<root>/stats.db` next to the module cache. There is no flag or env
var for it; systemd deployments keep the database outside the cache, so
wiping the cache leaves the history intact (an unprivileged fallback stored
next to the cache is lost with it). The module cache root
itself is `-root` flag > `CACHE_ROOT` env (dedicated path/disk for module
storage) > `cache`. The legacy `stats.json` lookup follows the database
directory. Nightly archives live in `<db>.backup.daily/` beside it, so a
cache wipe and a history restore stay independent.

## Deployment (NixOS)

`systemd.nix` is a NixOS module fragment (same consumption pattern as
../zdash/systemd.nix, host infra flake modules list) exposing
`services.go-mod-proxy.{enable,bin,host,port,root,neighbourCaches}`;
`neighbourCaches` becomes `NEIGHBOUR_CACHES` when non-empty. It
deliberately runs a PERSISTENT server (`wantedBy = multi-user.target`, `Restart = always`,
network-online ordering), NOT socket activation: fleet toolchains must find
the proxy alive at any build time. Restarts are rate-limited (3 starts per
30s): a crashing binary ends in `failed` within seconds instead of
looping. Defaults: binary
`/nix/persist/root/bin/goproxy` (make build, manual deploy), cache root
`/nix/persist/cache/go/proxy`. Hardened: strict read-only FS plus
ReadWritePaths on the cache root, seccomp `@system-service` minus
{aio,keyring,memlock,setuid,timer}, zero capabilities (root kept only as
stable cache owner identity), SocketBind pinned to the single port (outbound
connect/DNS unaffected, no IP egress pinning since upstream fetch is the
job: never add `IPAddressDeny`/`IPAddressAllow` to the unit, they filter
both directions on the cgroup and an allow-list of loopback turns every
upstream dial into `dial tcp ...: i/o timeout`), MemoryMax 512M /
TasksMax 512 / LimitNOFILE 16384, full kernel/proc/
keyring/namespace protection. The host side owns ingress (caddy vhost +
listen IP, see ../nixos/server/all/go-mod-proxy01.nix).

`make deploy-test-nix` rolls a locally built binary onto the NixOS hosts:
it backs up the current `/nix/persist/root/bin/goproxy` to `.old` (keeping
the previous `.old2`), stops/restarts the `go-mod-proxy01` and
`go-mod-proxy02` units and replaces the binary in place. Both units are
stopped before the swap; `go-mod-proxy02` starts first so the fleet keeps a
warm cache online while `go-mod-proxy01` comes back. `sudo -v` runs first so
the later steps do not prompt mid-deploy.

`systemd-socket.nix` is the alternative on-demand fragment: a socket unit
owns `127.0.0.1:9091` and passes the descriptor via LISTEN_FDS
(`SOCKET_ACTIVATION=1`); the service has no `wantedBy` (the socket triggers
it), uses `Restart = on-failure` (idle exits are clean, must not loop) and
`EXIT_ON_IDLE=1`; caddy targets the socket address, which keeps accepting
while the service is down; `BIND_ADDR=127.0.0.1:9090` is the fallback for
manual starts without passed sockets.

## Fixed workflow — every task, no exceptions, ALWAYS: test, commit, push! ALWAYS, DO NOT ASK!

1. **Format + check**: `gofmt, go vet, go mod tidy -check`
2. **Build**: `go build -o goproxy ./cmd/goproxy`
3. **Test**: `make test` (to run all tests here, ensure its fully parallel).
   Real-network end-to-end tests are opt-in: `make test-e2e` sets
   `GOPROXY_E2E=1` and fetches `rsc.io/quote@v1.5.2` from proxy.golang.org,
   verifies it against sum.golang.org, and checks the dashboard/SSE path
   end to end. Without the env var (or without network) they skip, so
   `make test` stays hermetic.
4. **Generate**: make generate, include in commit 
6. **Commit**: `git add . && git commit -m '<useful commit message>'`.
7. **Tag**: bump the patch segment only, never reuse/move/delete a tag
   (the current series is `v0.1.x`): `git tag "$(git describe --tags --abbrev=0 | awk -F. -v OFS=. '{$NF++; print}')"`.
8. **Push**: `git pull && git pull --tags && git push && git push --tags`.

Notes: `-race` tests need `CGO_ENABLED=1` (dev/test only; the shipped binary is
built `CGO_ENABLED=0`). `make test-e2e` exercises the real upstream and
checksum database (`internal/proxy/e2e_test.go`, `cmd/goproxy/e2e_test.go`);
their expected hashes come from the published sum.golang.org record. Run a
local instance with
`./goproxy -addr 127.0.0.1:5100 -root /tmp/cache` and exercise it via
`GOPROXY=http://127.0.0.1:5100 go mod download <mod>@<ver>`; watch `/api/dashboard`
and `/api/history?range=24h` (also `7d`, `30d`, `1y`, `all`). Socket-activated
mode can be exercised without systemd: pass a listening fd as 3 with
`LISTEN_FDS=1`, `LISTEN_PID=$$`, `SOCKET_ACTIVATION=1`, `EXIT_ON_IDLE=1`
(internal/systemd/systemd_test.go re-executes the test binary this way).
`make screenshots` regenerates the README dashboard images from the seeded
demo archive; run it when the dashboard or its demo data changes.
